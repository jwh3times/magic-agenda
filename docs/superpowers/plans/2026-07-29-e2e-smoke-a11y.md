# E2E Smoke + A11y — Implementation Plan (Part 2A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Playwright smoke and accessibility tests against the Cloudflare Pages preview deploy of each PR, guarding the service-worker/CSP regression that shipped twice and installing an axe ratchet.

**Architecture:** A new `E2E` job in `ci.yml` discovers the PR's preview URL from the `Cloudflare Pages` check run, then runs Playwright against it. Specs live in `tests/e2e/` so they inherit Part 1's `npm test` exclude and tsconfig coverage. Sign-in happens once in a global setup and is reused via `storageState`; board state is seeded through a user-scoped Supabase client, never the service-role key.

**Tech Stack:** Playwright (Chromium only), `@axe-core/playwright`, `@supabase/supabase-js` (already a dependency), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-07-29-e2e-smoke-a11y-design.md` — Part 2A only. Visual regression is Plan B and depends on nothing here.

## Global Constraints

- **Branch:** work on `test/e2e-smoke-a11y` (already created off `main`, already holds the spec commit). `main` is PR-only; never push to it directly.
- **Target release version:** compute with `node scripts/next-version.mjs` at Task 7 — **do not hand-compute**, and do not trust a version written here, because merges to `main` move it.
- **`npm test` must stay hermetic.** It must never need Docker, a database, a browser, or a network. `tests/**` is already excluded; keep it that way. The pure helpers in `scripts/` DO run in `npm test` and must stay pure.
- **The production service-role key must never enter CI or this repo.** It bypasses RLS entirely. Seeding uses the anon key plus the test account's own credentials.
- **The `E2E` job must not be made a required check in this PR.** A required check whose workflow is not yet on `main` wedges every other open PR. Promotion is a separate step after merge.
- **Never trigger the job on `deployment_status`** — that shape is a required check that never runs.
- **Skips must succeed from inside a step, never a job-level `if:`** — same reason.
- **`noUnusedLocals` / `noUnusedParameters` are ON.**
- Verification commands: `npm test`, `npm run test:rls`, `npm run test:e2e`, `npm run lint`, `npm run format:check`, `npx tsc -b`.

## Prerequisites — the maintainer must do these before Task 3

Tasks 1 and 2 need none of this. Tasks 3–5 cannot be verified without all of it.

   - `E2E_TEST_EMAIL`

- [ ] **Step 3: Implement**

Create `scripts/preview-url.mjs`:

```js
#!/usr/bin/env node
/**
 * Resolve the Cloudflare Pages preview URL for a commit.
 *
 * This repository has NO GitHub Deployments -- Cloudflare Pages reports as a check run whose
 * details_url points at the Cloudflare dashboard, and no GitHub API surfaces the preview URL. So
 * the URL is derived from the deployment UUID embedded in that dashboard link:
 *
 *   details_url  .../pages/view/magic-agenda/15aaf5a2-379b-41c1-a55c-d6a4ece71cef
 *   preview      https://15aaf5a2.magic-agenda.pages.dev
 *
 * Verified against PRs #113, #114 and #115 before adoption. Both the details_url shape and the
 * URL convention are undocumented, so if either changes this returns null and the CLI exits 1
 * with a message -- it never falls back to guessing, and never silently tests production. The
 * recorded escape hatch is the Cloudflare Pages deployments API, which needs an API token.
 */
import { execFileSync } from 'node:child_process'

export const CLOUDFLARE_CHECK_NAME = 'Cloudflare Pages'
const PROJECT = 'magic-agenda'
const UUID_RE = /[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}/i

export function findCloudflareCheckRun(checkRuns) {
  if (!Array.isArray(checkRuns)) return null
  return checkRuns.find((run) => run?.name === CLOUDFLARE_CHECK_NAME) ?? null
}

export function previewUrlFromDetailsUrl(detailsUrl, project) {
  if (typeof detailsUrl !== 'string') return null
  const match = detailsUrl.match(UUID_RE)
  if (!match) return null
  return `https://${match[0].slice(0, 8).toLowerCase()}.${project}.pages.dev`
}

const POLL_INTERVAL_MS = 15_000
const TIMEOUT_MS = 10 * 60_000

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms))

async function main() {
  const sha = process.argv[2]
  const repo = process.env.GITHUB_REPOSITORY
  if (!sha) throw new Error('usage: node scripts/preview-url.mjs <sha>')
  if (!repo) throw new Error('GITHUB_REPOSITORY is unset')

  const deadline = Date.now() + TIMEOUT_MS
  for (;;) {
    const raw = execFileSync('gh', ['api', `repos/${repo}/commits/${sha}/check-runs`], {
      encoding: 'utf8',
      stdio: ['ignore', 'pipe', 'pipe'],
    })
    const run = findCloudflareCheckRun(JSON.parse(raw).check_runs)

    if (run?.status === 'completed') {
      if (run.conclusion !== 'success') {
        throw new Error(`Cloudflare Pages build for ${sha} concluded "${run.conclusion}".`)
      }
      const url = previewUrlFromDetailsUrl(run.details_url, PROJECT)
      if (!url) {
        throw new Error(
          `Could not derive a preview URL from details_url: ${run.details_url}\n` +
            'Cloudflare may have changed its dashboard link format. See the header comment in ' +
            'scripts/preview-url.mjs for the Cloudflare API fallback.',
        )
      }
      process.stdout.write(url)
      return
    }

    if (Date.now() >= deadline) {
      throw new Error(
        `No completed Cloudflare Pages deploy appeared for ${sha} within 10 minutes.\n` +
          'The preview may be slow, or Pages may not build for this PR (forks get no preview).',
      )
    }
    await sleep(POLL_INTERVAL_MS)
  }
}

// Only run the CLI when invoked directly, so importing the pure helpers in a test does not poll.
if (process.argv[1] && import.meta.url === new URL(`file://${process.argv[1]}`).href) {
  main().catch((error) => {
    console.error(error.message)
    process.exit(1)
  })
}
```

- [ ] **Step 1: Write the Supabase fixture**

Create `tests/e2e/fixtures/supabase.ts`:

```ts
import { createClient, type SupabaseClient } from '@supabase/supabase-js'

/**
 * A user-scoped client for the dedicated E2E account.
 *
 * Anon key plus the account's own credentials -- NEVER the service-role key. That key bypasses
 * RLS entirely, and putting it in CI would be a categorical downgrade of the boundary this whole
 * test effort exists to protect. Everything here is therefore subject to the same policies a real
 * browser is.
 */
function required(name: string): string {
  const value = process.env[name]
  if (!value) {
    throw new Error(
      `${name} is unset. E2E needs E2E_SUPABASE_URL, E2E_SUPABASE_ANON_KEY, E2E_TEST_EMAIL and ` +
        'E2E_TEST_PASSWORD -- see the Prerequisites section of the plan.',
    )
  }
  return value
}

export async function testClient(): Promise<SupabaseClient> {
  const client = createClient(required('E2E_SUPABASE_URL'), required('E2E_SUPABASE_ANON_KEY'), {
    auth: { persistSession: false, autoRefreshToken: false },
  })
  const { error } = await client.auth.signInWithPassword({
    email: required('E2E_TEST_EMAIL'),
    password: required('E2E_TEST_PASSWORD'),
  })
  if (error) throw new Error(`E2E test account sign-in failed: ${error.message}`)
  return client
}

export async function testUserId(client: SupabaseClient): Promise<string> {
  const { data, error } = await client.auth.getUser()
  if (error || !data.user) throw new Error(`could not read the test user: ${error?.message}`)
  return data.user.id
}
```

- [ ] **Step 2: Write the seeding fixture**

Create `tests/e2e/fixtures/seedBoard.ts`:

```ts
import type { SupabaseClient } from '@supabase/supabase-js'
import { testClient, testUserId } from './supabase'

/**
 * Resets the E2E account to a known board.
 *
 * Dates are absolute, not relative to "today", so the seeded rows land in the same cells on every
 * run. The axe baseline keys on CSS paths, so a board whose shape drifts would invalidate it.
 *
 * Column names are ROW shape, not app shape: `order_index` (not `order`, which is reserved SQL),
 * and `day` is a real NULL for the inbox rather than the app's `'inbox'` sentinel. That mapping
 * lives in src/data/mappers.ts and does not apply here -- see AGENTS.md.
 */
export const SEEDED_TITLES = ['Draft the launch note', 'Book the venue', 'Unscheduled idea']

export type Theme = 'cork' | 'brutal' | 'glass'

export async function seedBoard(theme: Theme = 'cork'): Promise<void> {
  const client: SupabaseClient = await testClient()
  const userId = await testUserId(client)

  const { error: deleteError } = await client.from('tasks').delete().eq('user_id', userId)
  if (deleteError) throw new Error(`seed: clearing tasks failed: ${deleteError.message}`)

  const { error: insertError } = await client.from('tasks').insert([
    {
      user_id: userId,
      title: SEEDED_TITLES[0],
      day: '2026-06-15',
      order_index: 0,
      status: 'todo',
      category: 'work',
      color: 'yellow',
    },
    {
      user_id: userId,
      title: SEEDED_TITLES[1],
      day: '2026-06-17',
      order_index: 0,
      status: 'doing',
      category: 'personal',
      color: 'blue',
    },
    {
      user_id: userId,
      title: SEEDED_TITLES[2],
      day: null,
      order_index: 0,
      status: 'todo',
      category: 'ideas',
      color: 'mint',
    },
  ])
  if (insertError) throw new Error(`seed: inserting tasks failed: ${insertError.message}`)

  // The signup trigger already created this row, so update rather than insert.
  const { error: settingsError } = await client
    .from('user_settings')
    .update({ theme, default_view: 'calendar', week_start: 0, timezone: 'UTC' })
    .eq('user_id', userId)
  if (settingsError) throw new Error(`seed: writing settings failed: ${settingsError.message}`)

  await client.auth.signOut()
}
```

- [ ] **Step 3: Write the global setup**

Create `tests/e2e/globalSetup.ts`:

```ts
import { chromium } from '@playwright/test'
import { mkdir } from 'node:fs/promises'
import path from 'node:path'

export const STORAGE_STATE = path.join('tests', 'e2e', '.auth', 'user.json')

/**
 * Signs in once per run and saves the session.
 *
 * Not per-test, for two reasons: it is slow, and `supabase/config.toml` limits sign-ins to 30 per
 * 5 minutes per IP. A shared CI egress IP plus per-test sign-in is a self-inflicted flake.
 */
export default async function globalSetup(): Promise<void> {
  const baseURL = process.env.E2E_BASE_URL
  if (!baseURL) {
    throw new Error(
      'E2E_BASE_URL is unset. These tests run against a DEPLOYED build (a Cloudflare Pages\n' +
        'preview in CI) because public/_headers is Cloudflare-specific.\n' +
        'Locally, point it at a preview URL or https://magicagenda.app.',
    )
  }
  const email = process.env.E2E_TEST_EMAIL
  const password = process.env.E2E_TEST_PASSWORD
  if (!email || !password) {
    throw new Error('E2E_TEST_EMAIL and E2E_TEST_PASSWORD must be set.')
  }

  await mkdir(path.dirname(STORAGE_STATE), { recursive: true })

  const browser = await chromium.launch()
  try {
    const page = await browser.newPage({ baseURL })
    await page.goto('/login')
    await page.getByPlaceholder('you@example.com').fill(email)
    await page.getByPlaceholder('Password').fill(password)
    await page.getByRole('button', { name: 'Sign in', exact: true }).click()

    // The board is the signed-in home route; waiting on its toolbar proves the session took.
    await page.getByRole('button', { name: '+ New task' }).waitFor({ timeout: 30_000 })
    await page.context().storageState({ path: STORAGE_STATE })
  } finally {
    await browser.close()
  }
}
```

### Task 4: Smoke spec

**Files:**

- Create: `tests/e2e/smoke.spec.ts`

**Interfaces:**

- Consumes: `seedBoard`, `SEEDED_TITLES` (Task 3).

These are **characterization tests against a deployed app**, not red-then-green TDD. They are expected to pass on first run; their value is that they fail when a future deploy regresses. Do not manufacture a red state. If one genuinely fails, that is a real finding — report it rather than adjusting the assertion.

- [ ] **Step 1: Write the spec**

Create `tests/e2e/smoke.spec.ts`:

```ts
import { expect, test, type ConsoleMessage, type Page } from '@playwright/test'
import { seedBoard, SEEDED_TITLES } from './fixtures/seedBoard'

// No fake clock in this file, deliberately. `page.clock` can invalidate Supabase's JWT expiry
// checks (the token was issued in real time) and may not reach the service worker's separate
// context -- and the service-worker test below is the single most valuable thing here.

/**
 * Console errors, minus the ones that are not ours.
 *
 * public/_headers records that Cloudflare's injected Web Analytics beacon changes its hash
 * without notice and silently re-breaks CSP. Unscoped, that event would turn every PR red for a
 * cause unrelated to any PR.
 */
const IGNORED = [/cloudflareinsights\.com/i, /static\.cloudflareinsights/i]

function collectErrors(page: Page): string[] {
  const errors: string[] = []
  page.on('console', (msg: ConsoleMessage) => {
    if (msg.type() !== 'error') return
    const text = msg.text()
    if (IGNORED.some((re) => re.test(text))) return
    errors.push(text)
  })
```

```ts
import AxeBuilder from '@axe-core/playwright'
import { expect, test, type Page } from '@playwright/test'
import { readFileSync, writeFileSync } from 'node:fs'
import path from 'node:path'
import { seedBoard, type Theme } from './fixtures/seedBoard'

// Installing the ratchet is in scope; fixing what it finds is NOT. theme/themeConf.ts is a
// deliberate verbatim port of the prototype, and turning this into a contrast redesign would be a
// different project. Existing violations are baselined; only NEW pairs fail.
const BASELINE = path.join('tests', 'e2e', 'a11y-baseline.json')

type Finding = { ruleId: string; target: string }

function readBaseline(): Finding[] {
  try {
    return JSON.parse(readFileSync(BASELINE, 'utf8')) as Finding[]
  } catch {
    return []
  }
}

const key = (f: Finding) => `${f.ruleId} ${f.target}`

async function scan(page: Page, label: string): Promise<Finding[]> {
  const results = await new AxeBuilder({ page }).analyze()
  return results.violations.flatMap((v) =>
    v.nodes.map((n) => ({ ruleId: v.id, target: `${label}:${n.target.join(' ')}` })),
  )
}

/** Set E2E_A11Y_UPDATE_BASELINE=1 to rewrite the baseline instead of asserting against it. */
const UPDATING = process.env.E2E_A11Y_UPDATE_BASELINE === '1'
const collected: Finding[] = []

test.afterAll(() => {
  if (!UPDATING) return
  const unique = [...new Map(collected.map((f) => [key(f), f])).values()].sort((a, b) =>
    key(a).localeCompare(key(b)),
  )
  writeFileSync(BASELINE, `${JSON.stringify(unique, null, 2)}\n`)
})

function assertNoNewViolations(found: Finding[]): void {
  if (UPDATING) {
    collected.push(...found)
    return
  }
  const baselined = new Set(readBaseline().map(key))
  const fresh = found.filter((f) => !baselined.has(key(f)))
  expect(fresh).toEqual([])
}

test.describe('signed out', () => {
  test.use({ storageState: { cookies: [], origins: [] } })

  test('landing has no new a11y violations', async ({ page }) => {
    await page.goto('/')
    await page.evaluate(() => document.fonts.ready)
    assertNoNewViolations(await scan(page, 'landing'))
  })

  test('login has no new a11y violations', async ({ page }) => {
    await page.goto('/login')
    await page.evaluate(() => document.fonts.ready)
    assertNoNewViolations(await scan(page, 'login'))
  })
})
```

Note also the gate's **first** condition. This workflow triggers on `push` to `main` as well as `pull_request`, and on a push event `github.event.pull_request` is null — so without that check the job would try to resolve a preview for an empty SHA on every merge.

```yaml
  E2E:
    runs-on: ubuntu-latest
    # One shared production test account, so runs must not overlap across PRs.
    # cancel-in-progress: false because a half-run suite leaves the account mid-seed.
    # ACCEPTED COST: GitHub keeps only one pending run per group, so if a third PR queues while
    # one runs and one waits, the middle one is cancelled and needs a manual re-run.
    concurrency:
      group: e2e-prod-account
      cancel-in-progress: false
    timeout-minutes: 25
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci

      # Both skips report SUCCESS from inside a step, never a job-level `if:`. A required check
      # that never runs leaves a PR unmergeable forever -- the same rule the Changelog job follows.
      - name: Decide whether to run
        id: gate
        env:
          HAS_SECRETS: ${{ secrets.E2E_TEST_EMAIL != '' }}
          IS_FORK: ${{ github.event.pull_request.head.repo.fork }}
          EVENT: ${{ github.event_name }}
        run: |
          if [ "$EVENT" != "pull_request" ]; then
            echo "Not a pull_request event ($EVENT): there is no preview to test. Skipping."
            echo "run=false" >> "$GITHUB_OUTPUT"
          elif [ "$IS_FORK" = "true" ]; then
            echo "Fork PR: Cloudflare builds no preview and secrets are unavailable. Skipping."
            echo "run=false" >> "$GITHUB_OUTPUT"
          elif [ "$HAS_SECRETS" != "true" ]; then
            echo "No E2E secrets available (Dependabot or unconfigured repo). Skipping."
            echo "run=false" >> "$GITHUB_OUTPUT"
          else
            echo "run=true" >> "$GITHUB_OUTPUT"
          fi

      - name: Install Chromium
        if: steps.gate.outputs.run == 'true'
        run: npx playwright install --with-deps chromium

      - name: Resolve the preview URL
        if: steps.gate.outputs.run == 'true'
        env:
          GH_TOKEN: ${{ github.token }}
          GITHUB_REPOSITORY: ${{ github.repository }}
        run: |
          URL="$(node scripts/preview-url.mjs "${{ github.event.pull_request.head.sha }}")"
          echo "Preview: $URL"
          echo "E2E_BASE_URL=$URL" >> "$GITHUB_ENV"

      - name: Run the E2E suite
        if: steps.gate.outputs.run == 'true'
        env:
          E2E_TEST_EMAIL: ${{ secrets.E2E_TEST_EMAIL }}
          E2E_TEST_PASSWORD: ${{ secrets.E2E_TEST_PASSWORD }}
          E2E_SUPABASE_URL: ${{ secrets.E2E_SUPABASE_URL }}
          E2E_SUPABASE_ANON_KEY: ${{ secrets.E2E_SUPABASE_ANON_KEY }}
        run: npm run test:e2e

      - name: Upload traces on failure
        if: failure() && steps.gate.outputs.run == 'true'
        uses: actions/upload-artifact@v4
        with:
          name: playwright-traces
          path: test-results/
          retention-days: 7
```
